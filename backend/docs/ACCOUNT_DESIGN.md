# 账号与归属设计 · 2026-09-28

2026-10-05 实施：单机三级账号已接入真实数据库、API、Vue 左侧「账号」入口与 HTTP/WS/构建租户隔离。既有超管、编号、设备、Android 模板保持不变；2026-10-05 追加到期总台设备自动归超管；多服务器、手动设备下发、付款/订单和机器人验证码仍为规划。

## 已实现：超管 → 总台 → 子账号

超管创建总台（studio_admin）；总台最多启用 5 个子账号（member）。各总台拥有独立 project_id，子账号只看自己归属的设备及自己提交的构建。左侧入口位于设备之后；服务器/协议日志与构建环境维护仅超管。实现入口：account-hierarchy.js、account-management.js、Accounts.vue；详见第 5 节。

- Vue + Node 同域运行，SQLite 位于 `backend/.node-private/boundary.sqlite`。旧 PHP 运行数据已移出项目私有备份，不参与当前运行。
- 全新数据库首次访问 `/install` 设置唯一初始超管账号和任意非空密码；密码与确认密码可同时切换显示。服务端事务创建账号、固定 APK ID `1` 与审计记录，密码以 Argon2id 散列保存。成功后生成私有完成锁并永久关闭账号初始化；登录账号仍可在 `/install` 检测或补齐构建环境。重启不重置密码，不重复创建账号。已有超管的旧实例升级时自动补写完成锁。
- 打开 [登录页](http://127.0.0.1:8080/login)，登录后右上角「账号设置」支持退出与修改密码。
- 使用 Passport Local/JWT 与 jose。HTTP Token 有效期 8 小时；浏览器使用 HttpOnly、SameSite=Strict、Path=/api 的 Cookie，不将 Token 放入 localStorage。Bearer Token 可用于本机 API 调试，两者同时存在时以 Authorization 为准。
- 每个账号在 SQLite 只保留一个有效 `session_id`。新登录替换旧会话；旧 Token/图片/导出/API 请求立即失效，已有面板 WS 收到会话结束通知，旧页面返回登录。
- 同一浏览器共享 Cookie 的标签页属于同一次登录；「单端」指单个有效登录会话，不是只能打开一个标签页。IP 不作为设备身份。
- 退出、改密撤销当前会话，WS 也断开。账号停用或角色变化会在每次 HTTP、WS 业务消息及广播时重新检查。
- 管理端业务 API 均需登录；当前 B 包自动上线路由按固定 APK ID 确定账号并静默签发设备 Token，后续上报校验该 Token。旧短效登记接口仅兼容旧包。面板 WS 使用从登录态换取的 10 分钟专用票据，与 HTTP Token 和设备凭证相互隔离。
- 登录失败与改密校验采用限流；账号审计仅保存事件、操作者 ID、IP 和时间，不保存密码、验证码、Token 或请求正文。
- 超管跨所有 `project_id` 查看设备、历史记录和现有管理功能。设备与快照的关联完整性、图片路径检查、正文剔除仍然保留。
- 已有管理功能包含列表、备注、查看、导出、新设备登记及查看租约内的实时最新帧；没有输入控制或完整诊断会话。

服务仍仅绑定 127.0.0.1，并保留 Host、Origin、转发头与同源 JSON 写请求检查。默认密码仅用于本机初始化；对外部署前更换密码、启用 HTTPS/WSS、完善租户隔离与访问审计，另做部署验收。当前并非公网成品。

## 账号卡与有效期基础：已实施

- 顶栏沿用紧凑卡片：头像字母、账号名、`角色 · APK 1`、有效期徽标。参考图只用于布局，账号、APK ID 和日期来自当前登录账号的服务端数据。
- APK ID 取 `accounts.apk_id`，一个账号一个固定编号，创建账号通过 `createAccountWithApkId` 在同一事务写入账号、分配编号并创建 `apk_routes`；任一步失败会整体回滚，用户只读。不是「总台 AppID」，不是构建 UUID，也不随构建增加或更换。`011_unique_account_apk_sequence` 新增持久化全局分配器：超管固定为 `1`，后续总台和子账户共用从 `100` 开始的单调递增编号；数据库事务、账号唯一约束和路由主键共同防止重复。停用或删除账号不回收编号，旧数字路由会推进或跳过分配器，重启后从已保存的位置继续。
- 增量迁移 `008_account_apk_id` 新增唯一账号编号及构建归属快照；`009_superadmin_apk_id_1` 将现有默认超管的规范编号固定为 `1`。旧 `10074` 等路由继续作为兼容别名保留，已有设备、历史构建和旧 APK 不改写；新账号统一从全局 APK ID 分配器取号，不依赖内部账号 ID，不重新分配或恢复停用路由。
- SQLite 增量迁移 `007_account_validity` 添加 `accounts.valid_until`，UTC 毫秒截止时间，区间为 `now < valid_until`；原超管默认 `NULL`，表示长期有效，不改账号密码、归属或会话。
- `/api/auth/login` 和 `/api/auth/me` 的 `user` 新增 `apkId: string`、`validUntil: number | null`。原 `expiresAt` 仍是登录会话期限，不拿它显示续费到期日期。
- 日期按北京时间显示最后有效日。未来开通时选择「2026-10-11 到期」，服务端应保存 `2026-10-12T00:00:00+08:00` 对应的 UTC 毫秒值，10 月 11 日全天有效，到次日零点终止。正常日期用绿色，剩余 7 天以内用橙色，到期用红色；未知字段显示待确认，不当作长期有效。
- 服务端登录事务重新读取有效期，HTTP、面板 WS 消息与广播均检查有效期；签发的登录会话截止于 `min(当前时间 + 8 小时, valid_until)`，面板票据也不超过该会话。到期后旧会话不再访问设备、构建、下载等管理 API。扩展账号有效期不延长旧会话，重新登录取得新会话。
- 本次没有账号有效期修改入口，也没有放开总台/子账号登录。超管仍是唯一可登录角色；限期显示分支使用独立测试数据验收，不给当前超管填虚构日期。

## 层级规则与后续扩展

### 1. 账号层级

| 角色 | 建议范围 |
|---|---|
| 超管 | 全部工作室、全部设备、创建总台、归属调整及审计 |
| 总台 | 自己的工作室设备与配置；创建最多 5 个启用子账号（到期仍占位，停用释放）；工作室内部下发设备 |
| 子账号 | 仅被分配给自己的设备及允许的功能 |

总台对应工作室租户，服务端内部使用 `studio_id` / `project_id` 做隔离。这些是内部归属主键，**不叫 AppID，也没有「总台 AppID」这一业务字段**。本轮没有提前加入租户表、创建账户路由或虚假的管理按钮。

本次已将所有查询、图片/导出、WS 订阅和广播统一校验角色与归属，不能只隐藏前端列表。5 个启用子账号的限额在数据库事务中检查，创建和重新启用均检查；到期仍占名额，避免续期后同时恢复超过 5 个。父账号停用时一并撤销相关会话。

### 1.1 总台开通、到期与续费

1. **计费单位为总台 / 工作室**，超管负责开通和续期。创建总台时必须给出期限，不把空值默认为付费总台的长期许可；超管自身默认长期有效。先支持人工确认续费，不提前接支付平台。
2. 子账号默认继承总台期限；若另设子账号期限，有效截止时间取两者较早值。总台到期，旗下全部账号暂停管理权限；并发创建和重新启用仍受每总台最多 5 个启用子账号约束；到期账号仍占位，停用才释放。
3. 未到期续费从原截止时间续接，已到期续费从当前时间开始，即基准 `max(now, 原截止时间)`。首版建议明确按天购买（北京时间自然日截止）；若后续按自然月出售，单独确定月底规则，不把一个月默认为 30 天。
4. 续期操作在服务端事务内完成：校验操作者及租户范围、幂等业务单号、旧/新有效期、续期天数和审计。普通总台/员工不自行写入期限；客户端传入的期限不作为权限依据。支付接入后以验签回调和订单状态为准，不信任支付成功跳转页面。
5. 开通、停用、调整期限及续费统一重算总台与子账号权限，撤销受影响旧会话和 WS 订阅，重新登录才恢复。保留账号、APK 路由和历史记录。总台达到截止时间且没有提前续期时，旗下总台/子账号设备自动转给固定编号 1 的超管，并转入平台 project_id；不删除设备或操作手机数据。接管结束原会话、WS 订阅、查看租约与临时图片/节点/诊断缓存；旧设备项目 JWT 失效，已登记设备通过原 APK ID 重新上线取得平台 JWT。到期路由不接收新设备，不把整个 APK ID 路由重定向到超管。续费只恢复账号期限，已接管设备不会自动归还。
6. 总台到期后登录提示联系平台续费；员工提示联系总台。即将到期提醒可以后续通过所属机器人发送，避免每次页面请求重复通知。机器人、专属域名和服务器均不绕过中央有效期校验。

本次已实现开通、期限调整、继承、会话与设备接入到期联动；支付订单、自动续费和机器人提醒仍未接入。

### 2. 只有 APK ID：区分构建、路由与凭证

- `APK ID`：创建账号时分配的固定业务编号；初始超管为 `1`。构建参数只用于选择接收账号，公开编号不具备身份验证能力。
- `构建 ID`：一次具体构建任务的标识，例如 `5412ce7f`，与 APK ID 分开。一次 APK 配置可有多个构建版本。
- 域名：负责连接到哪个服务入口；APK ID 负责查默认归属。域名不是用户账号，也不是权限凭证。
- 用户专属 APK 默认进入该用户的设备列表；总台 APK 先进入该总台待分配池；超管 APK 可进入平台待分配池，再经后台操作指定工作室与用户。
- 设备首次登记后，实际归属保存在服务端。后续下发更新服务端归属和审计，重新计算可见性/订阅并撤销旧权限；设备重新连接不得覆盖已生效的分配结果。
- APK ID 可公开，不能单独凭它信任数据或访问其他设备；每台设备仍需独立登记凭证，服务端校验设备与项目关系。

### 当前构建归属解析（已实现）

| 输入 | 构建结果 |
|---|---|
| 留空、空白或省略 apkId | 使用默认接收账号的固定编号，`default_empty` |
| 匹配本项目启用且未到期的账号固定编号 | 使用该账号及其编号，`explicit` |
| 格式正确但不存在、已停用、已到期、属于其他项目或仅为旧别名 | 使用默认接收账号，`default_unmatched`；不修改目标映射 |
| 超长、控制符、非编号字符 | 422 字段校验错误，不进入队列 |
| 默认接收账号/对应路由已停用 | 409，不生成无接收方的 APK |

默认接收方由服务端身份确定：超管默认本人，总台默认本人，子账号留空或填错归其总台。普通账号只能解析本工作室编号；超管可明确指定有效总台/子账号编号并按目标项目构建。域名不授予权限。

- 解析在构建入队事务内完成；`apk_builds.apk_id` 是最终写入 APK 的实际编号，另存 `requested_apk_id / owner_account_id / owner_username / routing_reason` 供回执与构建记录展示。相同 requestId 重试读取原记录，不重新决定归属。
- 构建不创建账号/路由，也不覆盖已有设备归属。旧任务保留原始记录与 APK，不冒充已按新规则构建。
- `POST /api/apk-routes` 已移除；`GET` 保留供接入调试兼容旧 APK。当前账号页不显示登记码入口；B 包调用 `/api/client/online` 后由服务器按实际 APK ID 固定归属并自动返回独立设备凭证，之后重连继续使用该归属。

当前接入副本已经使用 APK ID 查后台默认归属，并保存设备实际 owner_account_id；目前只配置到超管。未实现总台/子账号、归属下发、旧设备恢复或多域名部署；原浏览器模板保持不变。

### 3. 专属域名、专属服务器与中央数据库

完整的数据流、首次上线、超管汇总、临时截图读取、节点断联及分期交付方案见 [多服务器设计](MULTI_SERVER_DESIGN.md)。该文为后续设计，当前域名字段仅写入 APK 连接配置，尚未绑定工作室或节点。

建议先用单 Node 服务与 SQLite 验证账号逻辑，再逐步拆分部署，而非现在启动微服务：

1. 一个工作室绑定一个经过验证的域名；服务端维护域名到工作室的映射，拒绝未知 Host。域名映射不替代账号权限校验。
2. 初期多个域名可指向同一服务与数据库；总台只访问自己的租户数据，超管保留全局视图。
3. 需要专属服务器时，中央服务保留账号、归属、构建配置和审计的权威数据。专属节点以工作室限定的服务凭证调用中央 API，断联时停止需要新权限确认的操作，不擅自扩大权限。
4. 不让多台服务器经共享磁盘直接读写同一 SQLite 文件；达到多节点/写入量需求后，迁移至集中 PostgreSQL/MySQL，或者继续由中央单服务独占 SQLite 并通过 API 访问。该数据库迁移尚未实现。

按「平台统一持有数据库、总台管理自己工作室数据」理解当前意图；若以后每个总台独立持库，需另定平台汇总和数据同步边界。

### 4. 总台机器人验证码

后续每个总台配置自己的机器人 Token（加密存储），用户经一次性短效绑定链接绑定 Telegram 私聊身份，不仅凭用户名绑定。登录流程建议：

1. 账号密码验证成功，生成短效登录挑战，此时还不签发账号 Token。
2. 为该挑战生成 6 位随机验证码，通过所属总台机器人发送给已绑定的私聊；显示用户、服务端获取的 IP 和 5 分钟有效期。
3. 只保存带服务端密钥的验证码校验值，绑定账号和挑战；一次使用、限次验证、限速发送。重发撤销旧验证码，成功或到期删除挑战。
4. 验证成功后再创建唯一会话并挤下旧登录；不让仅输入正确密码的人提前挤下正在使用的账号。
5. 机器人失联、未绑定、重绑定与丢失账号的人工处理流程需单独设计；错误和日志不记录验证码正文。平台超管的机器人归属也在这一阶段单独配置。

以上均为规划。当前账号密码可直接登录，机器人验证码尚未启用。

### 5.2 左侧放「账号」，与右上角个人设置分开

新增 `/accounts`，放在「设备」之后；原有设备、构建、翻译、日志的相对顺序不变。

```text
超管左侧                 总台左侧                 子账号左侧
设备                     设备                     设备
账号 ← 总台管理          账号 ← 子账号管理        构建（仅自己的任务）
构建                     构建
翻译                     翻译
日志（服务器 / 协议）

右上角账号卡 → /settings/account → 查看自己的编号/有效期、改密、退出
```

- 超管进入「账号」默认显示 **总台管理**，右上角按钮为「新建总台」。每行提供「管理子账号」进入 `/accounts/:studioAccountId/members`；此处可以代管该总台的子账号。
- 总台进入同一 `/accounts` 显示 **子账号管理**，右上角按钮为「新建子账号」，展示「已启用 N / 5」。不提供创建总台、修改自身期限或访问其他总台的入口。
- 子账号不显示「账号」和「日志」，保留自己的账号卡和既有设备/构建功能。翻译配置仅总台维护，子账号可以使用本工作室已启用的翻译功能，不能读取或修改密钥。
- 账号入口沿用窄侧栏、56px / 64px 和 1280px 最小桌面画布；可复用本地 `shield-check.svg`，不扩大成大侧栏、不新增手机断点。
- 页面用现有 Tabler 紧凑表格和表单，不在右上角个人设置里塞入总台创建入口。
- 菜单隐藏和路由守卫只做交互；服务端仍逐个验证操作者角色、目标工作室和目标账号。

### 5.3 角色与权限矩阵

角色代码沿用 `superadmin` / `studio_admin` / `member`，不再增加一套 `studio` 或 `subadmin` 名称。

| 操作 | 超管 | 总台 | 子账号 |
|---|---|---|---|
| 新建总台 | 是 | 否 | 否 |
| 新建子账号 | 指定总台下代管 | 仅自己的总台下 | 否 |
| 查看账号列表 | 全部总台；指定总台的子账号 | 仅自己的子账号 | 否；仅个人资料 |
| 启用/停用、重置密码 | 所管理总台及其子账号 | 仅自己的子账号 | 仅自己的改密/退出 |
| 总台期限与续期 | 是 | 查看自己的期限 | 查看继承期限 |
| 子账号期限 | 在总台期限以内设置 | 在自己期限以内设置，可恢复继承 | 无修改权 |
| 设备列表/详情/统计 | 全项目 | 自己工作室 | 同工作室且当前分配给自己 |

总台和子账号不能创建超管、修改角色、修改父级、重写 APK ID 或指定任意 `project_id`。初版不设置硬删除账号按钮；停用保留账号、设备、编号及历史记录。

### 5.4 表单、列表与真实反馈

**新建总台**（超管）：总台名称、账号、初始密码/确认密码、到期日、备注。到期日必填；不能通过留空获得长期许可。账号沿用 3–32 位字母/数字/下划线及小写规范；新建账号初始密码建议至少 8 位、上限 128 字符。用户名、APK ID 创建后只读；服务端事务自动分配 APK ID，不放手填编号输入。

**新建子账号**（总台）：账号、初始密码/确认密码、备注；默认勾选「继承总台有效期」，允许选择更早的到期日。上级展示当前总台及期限，只读；请求不接收操作者自行指定的角色、上级或工作室。超管代管时由明确的总台路径确定目标。

**列表**：账号、固定 APK ID、角色/上级、启用状态、有效期、创建时间、操作；总台列表增加工作室名称和「已启用 N / 5」。未接入的最后登录信息不造值。分页、搜索和排序由服务端白名单处理，每页 20 条；排序字段先限定为账号、编号、创建时间和有效期。

**反馈**：提交中禁用重复提交；成功后显示实际创建账号和固定 APK ID，刷新列表，不声称已创建并未落库的账号。用户名重复、超过名额、无效日期或超过父级期限显示字段/业务错误。创建成功及关闭表单时清空密码；密码不回显于列表、日志或成功回执。模态表单支持标签关联、键盘 Tab、Esc 关闭及焦点恢复。

### 5.5 数据模型：用现有 project_id 作为唯一租户维度

增量迁移 `017_account_hierarchy` 已实现以下模型，先登记历史项目编号，再分配新总台项目；无数据重置。

| 表 / 字段 | 设计 |
|---|---|
| `projects` | `id`、名称、类型（平台/工作室/历史范围）、创建时间；租户主键统一为现有 `project_id` |
| `studios` | `project_id` 主键并关联 `projects.id`；唯一 `owner_account_id` 关联总台账号；创建时间。总台启用状态和期限以该账号为权威，不重复保存另一份 |
| `accounts.project_id` | 总台/子账号必填；超管为 NULL 并依角色授予全局权限。NULL 本身不是全局权限 |
| `accounts.parent_account_id` | 子账号必填并关联同项目的 `studio_admin`；总台和超管为空；不允许客户端任意改写 |
| `accounts.valid_until` | 总台必填有限期限；子账号 NULL 表示继承，可保存更早的独立截止；超管 NULL 表示长期有效 |
| `accounts.note` | 账号备注，最多 200 字符；文本展示，不解析 HTML；创建表单备注真实落库 |
| `accounts.creation_request_id` | 唯一幂等创建编号，与操作者、目标上级及非秘密创建字段绑定；相同编号只返回原结果，不保存密码原文/请求正文 |
| `account_audit` 扩展 | 目标账号、project_id、事件、操作者、时间、结果和非秘密期限/状态变化；不得存密码、摘要、Cookie、Token 或节点正文 |

数据库对用户名、APK ID、创建幂等编号、总台所有者使用唯一约束；账号工作室、上级、路由使用外键并建立工作室/上级/状态索引。角色与上级同工作室关系由服务端事务重新读取验证，不能把仅有外键当成完整权限控制。

迁移先登记所有既有业务表中的 project_id，再分配新工作室主键，避免覆盖旧项目。既有超管及其 APK ID 1、旧路由、设备/构建归属保持原样；现有 project_id 1 不自动变成第一个新总台的工作室，不把现有设备批量分给新账号。新总台在一个事务中创建新项目、账号、编号/路由和 studios 关系。

与多服务器规划衔接时，仍以 project_id 为权威；不另加含义冲突的 studio_id，不改域名/服务器部署。只有中央服务分配 APK ID，不让节点或浏览器自行取号。

### 5.6 原子创建与 5 个名额

1. 先验证登录态、有效期限、角色和白名单输入；密码散列复用现有 Argon2id，不自写散列或认证。
2. SQLite 写事务中重新读取操作者、总台状态和期限。总台创建仅超管可执行；子账号创建目标总台必须启用且未到期。
3. 初版沿用 5 个名额，明确计数为 **该总台下 enabled=true 的子账号**；到期仍占名额，停用释放。否则到期后腾位、总台续期会使超额子账号一起恢复。创建、重新启用都在同一事务内检查名额。
4. 使用现有 `createAccountWithApkId(trx, values, projectId)` 创建账号并分配固定编号/路由；同时保存关系、创建幂等编号和审计，任一步失败整体回滚。
5. 同一幂等编号重试返回原账号，不再分配编号，也不再次改写密码；操作者/目标/非秘密字段不一致时返回 409。表单修改字段后生成新创建编号。重复用户名不能产生孤立 project、studio 或 APK 路由。
6. 第 6 个启用子账号返回 409；两个请求争最后一个名额时只能一个成功。不得用先查询数量、事务外再插入的方式处理；SQLite 写冲突若重试，必须整事务重读身份和名额，不复用旧计数。
7. 停用后重新启用仍检查名额、父级状态和期限；停用/恢复不回收或更换 APK ID，不改变已有设备归属。账号续期不自动开启此前被手动停用的账号。

### 5.7 已实现 API

| 方法 / 路径 | 操作者 | 服务端确定的范围 |
|---|---|---|
| `GET /api/accounts` | 超管 / 总台 | 超管查看总台或指定总台子账号；总台只返回自己的子账号；子账号 403 |
| `POST /api/accounts/studios` | 超管 | 固定创建 studio_admin，自动创建项目并分配编号 |
| `POST /api/accounts/members` | 总台 | 固定创建 member；上级与 project_id 从当前总台取得 |
| `POST /api/accounts/studios/:studioAccountId/members` | 超管 | 明确指定一个有效总台代管创建，不接受另一个项目字段覆盖 |
| `PATCH /api/accounts/:id/status` | 超管 / 所属总台 | 总台仅自己子账号；禁用后撤销目标会话；总台停用联动全部子账号 |
| `PUT /api/accounts/:id/password` | 超管 / 所属总台 | 仅所管理目标，设置新密码并撤销目标会话，不读取原密码 |
| `PATCH /api/accounts/:id/validity` | 超管 / 所属总台 | 总台只改自己子账号，且不得超过总台期限；超管管理总台期限 |
| `GET /api/auth/me`、原个人改密/退出接口 | 已认证账号 | 仅本人资料及自己的会话，沿用现有入口 |

总台路径中的他人账号、猜测的跨项目 ID，以及不存在的对象统一返回 404；合法管理者仍能列出和恢复停用的目标账号，不能把「目标停用」当成禁止恢复的条件。操作者和父级停用则停止普通账号管理访问；无账号管理角色返回 403；未登录或会话失效返回 401；输入校验 422，重复账号/幂等冲突/名额不足 409。写请求继续要求同源 JSON、`X-Boundary-Request: 1` 和既有限流，客户端提交敏感字段采用严格白名单并剔除日志。

### 5.8 期限继承、会话撤销和数据隔离

```text
有效截止(总台) = 总台 accounts.valid_until
有效截止(子账号) = min(总台截止, 子账号独立截止或 +∞)
可登录/访问 = 本账号启用且未到期 AND 总台启用且未到期（对子账号）
会话截止 = min(当前时间 + 8 小时, 有效截止)
```

- 子账号数据库期限为 NULL 时，个人卡显示父级的实际截止及「继承总台」，不能显示长期有效；HTTP `user.validUntil` 返回有效截止，另以明确字段标记继承模式，`expiresAt` 仍是会话截止。
- 到期日按北京时间最后有效日处理，存次日零点对应 UTC 毫秒；例如选择 2026-10-11，截止为 2026-10-12 00:00:00+08:00。总台调整/缩短期限立即影响子账号，不靠浏览器日期判断。
- HTTP、WS 握手/每条业务消息/广播、图片及构建读取、后台任务发布前均重新校验本账号与父级。不能只在登录时校验一次；清理定时器只用于及时结束连接和租约，不替代请求校验。
- 停用、改密、期限变化撤销受影响会话和 WS 订阅，清理相关查看租约/临时缓存；父级停用/到期同时影响全部子账号。已有记录、设备和 APK ID 保留，不操作或清除手机数据。
- 请求获得不可变的 AuthContext（actorId、role、projectId、parentAccountId、effectiveValidUntil），从认证和数据库关系生成，不从请求体/域名/公开 APK ID 获得管理权限。不得每请求修改全局 Store 的 projectId，避免并发工作室互相串范围。
- 设备查询统一复用范围规则：超管跨项目；总台按 devices.project_id；子账号再加 devices.owner_account_id。详情、备注、备忘、拉黑/删除、快照/图片/导出、统计和 WS 订阅/广播/状态查询同样检查对象归属；不能只有列表过滤。
- 共享实时状态可沿用现有内存源，但向浏览器的对象查询、统计和推送必须经过请求/订阅授权。缓存和查看租约带项目、设备和会话关联；改归属后先结束原租约/订阅，再让新归属重新访问。
- 工作室内归属调整保留同一 project_id；跨工作室移动不塞进账号创建接口。旧设备重连不能恢复旧归属。无障碍、截图和现有手机本机确认流程保持不变。
- 翻译配置按当前工作室读取；构建、安装器关联 B 包、构建状态/明细和删除按工作室/操作者范围校验。全局服务器及协议日志仍仅超管。已公开的随机 APK 分享链接继续沿用原产品行为，不因此开放构建管理或日志；需要未来账号撤销分享时另定产物分享规则。
- 构建的「任务创建者」与「APK 接收账号」分开：子账号按 `actor_id` 读取自己的任务，不因为留空编号回落到总台就失去自己任务的访问，也不按接收账号获得其他人的构建明细。A 包锁定 B 包时同时校验项目与可访问任务范围；子账号仅引用自己已成功的 B 包，总台可管理本工作室，不能直接沿用全局 latestB 查询。
- 总台/子账号构建留空或无可用编号时回落到自己的总台；本工作室可用编号显式选择。格式正确但属于其他总台的编号按不可匹配处理，不泄露对方信息、不改路由。B 包自动上线还要核验 APK 路由、设备实际归属、账号/父级状态；无需修改 Android 权限或偷偷扩展采集。

### 5.9 实现与验收门槛

关系迁移、角色/父级/有效期计算集中在 `backend/src/account-hierarchy.js`；事务和管理 API 在 `backend/src/account-management.js`，Vue 使用 `frontend/src/pages/Accounts.vue`。Store.withScope 每请求生成独立范围并共享实时状态；设备挂载守卫也检查 URL 编码后的 ID。WS 每次业务消息、广播和订阅推送重读会话和对象范围。改密/停用/期限变化撤销目标及总台的子账号会话，清理设备连接、租约和缓存；新增角色已在全部隔离测试通过后接入 Passport。

创建幂等只保存操作者与非秘密字段，不保存密码原文/正文。总台名称/备注创建时落库；本轮不提供改名、备注编辑、设备重新分配或账号硬删除。付款、验证码、独立服务器仍留在后续阶段。

验收使用隔离数据库与明确的合成账号，不创建线上账号，不删除当前工作区代码：

1. 超管建总台；总台登录后建子账号；子账号只见自己的设备、构建和个人资料。
2. 两个工作室 A/B，以及 A 的两个子账号，分别通过 URL/API/图片/导出/统计/WS 猜测对方资源；均无跨范围数据、元数据、推送或租约泄漏。
3. 无权限角色没有菜单，直接打开账号/日志路由被拦截；API 独立拒绝，伪造 role/project_id/parent/APK ID 不提权。
4. 重复用户名、重复提交/幂等冲突、失败回滚、非法日期、NULL 继承、超过父级期限、最后一个名额并发及重新启用均有测试；总台续期后仍不超过 5 个启用子账号。
5. 父级停用/到期、密码重置及期限变化即时终止受影响会话/WS/查看租约；另一工作室不受影响，人工停用不被续期自动恢复。
6. 原超管登录/编号/数据、已装 APK 路由、构建成功产物链接和无障碍流程不变；迁移可重复运行，不重置用户名/密码/设备归属。
7. 桌面、800px 窄窗横向滚动、键盘表单、取消/失败反馈通过；运行 `npm run check`、`npm run test:e2e` 并单独报告新账号流程的真实结果。

### 5.10 到期总台设备自动归超管（2026-10-05）

- 服务启动时补处理，空闲时每 5 秒检查；业务 API 与设备凭证解析前也检查。按服务器 UTC 毫秒比较，`now >= valid_until` 触发，没有额外宽限期。总台及所属子账号的全部设备纳入接管；软删除、拉黑、凭证撤销状态不改变。单独停用总台、单个子账号到期不触发接管。
- 增量迁移 `018_studio_expiry_takeover` 只增加 `studio_expiry_takeovers` 与 `device_expiry_takeovers`。前者以总台 ID + 截止时间唯一，记录接管时间/超管/平台/设备数量；后者关联每台设备与原所有者，重试和服务重启不重复接管。零设备总台也记录一次处理。
- SQLite 同一事务更新 devices.owner_account_id/project_id，以及设备关联 snapshots、lab_events、device_memos、device_debug_reports 和协议日志的项目。设备 ID、APK ID、图像路径、原文剔除策略、注册时间和独立设备凭证不变；账号固定编号、APK 路由和历史构建不改写。账号审计记录非秘密接管元数据，超管服务器日志记录接管成功/失败重试。

- 本地验证使用隔离合成账号、设备、数据库及 WS；自动重连协议验证不等同于 Android 手机实机测试。
