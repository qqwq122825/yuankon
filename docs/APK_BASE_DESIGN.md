## 2. 固定模板与构建配置

采用从仓库固定源码模板构建，不对成品 APK 做替换字节或反编译改包。模板逻辑统一维护，任务只提供经过校验的数据。

| 字段 | 来源与规则 |
| --- | --- |
| `application_id` | 可输入或自动生成；每段只接受规定字符，限制长度。仅传给 Gradle 属性，保持源码 namespace 固定 |
| `app_name` | 1–40 字符，作为资源值写入，处理 XML/Android 字符串转义 |
| `icon` | PNG/JPEG，2MB/400 万像素以内；重新编码为固定尺寸 |
| `home_url` | 内置 WebView 的 HTTPS 主页，与通信地址分开 |
| `api_base_url` | 管理员预先登记的 HTTPS 接收地址，机器人选择配置档；不从主页推导 |
| `build_id` | 服务端生成的构建 UUID，用于关联版本，不是认证凭证 |
| `template_version` | 固定模板版本，便于复现 |
| `version_code`、`version_name` | 由构建任务管理；同一应用升级保留 applicationId/签名并递增 versionCode |
| `signing_profile` | 服务端引用，私钥留在构建主机，不交给机器人用户、不打入 APK |

日常交互只需名称、图标、主页；包名和通信配置提供默认值，确认页支持修改。通信地址使用项目默认配置，因此无需每次重复输入。

配置示意（仅示意，尚未部署该接口）：

```json
{
  "application_id": "cc.jk92.researchbrowser",
  "app_name": "研究浏览器",
  "home_url": "https://example.com",
  "api_base_url": "https://yk.jk92.cc/api/v1",
  "build_id": "SERVER_GENERATED_UUID",
  "template_version": "browser-v1",
  "telemetry_enabled_by_default": false
}
```

APK 内只放公开配置，Telegram Token、后台管理员凭证和共享设备密钥都留在服务器。`api_base_url` 只用于配对和单向诊断提交，不提供远程脚本、任意命令或设备控制接口。

## 3. 客户端模块

1. `BuildConfigReader`：读取本次构建的公开配置并校验。
2. `BrowserActivity`：显示主页、域名、刷新和返回；网页加载与研究权限无关。
3. `PairingScreen`：显示接收服务器、用途和字段清单，用户确认后使用短时一次性配对码。
4. `DiagnosticReporter`：只接收固定诊断事件类型；统一白名单、批次、去重和失败退避。
5. `ReportingSettings`：查看上报状态、暂停、撤销配对、清除待发队列。

浏览器不获得原生桥接对象去读取诊断凭证；网页内容也不能自行开启上报。第一版仅在用户打开应用且主动开启诊断会话期间提交，不加入开机启动、后台驻留或隐蔽持续采集。

无障碍权限状态、诊断开关、连接状态分别展示，不把“权限已开”当作“设备已在线”。本版浏览器 uses-permission 仍仅 INTERNET，状态验证服务没有采集能力，研究采集模块另行实现。

## 4. 上报数据范围

第一阶段只收集本应用的诊断信息：

- 构建 ID、模板/应用版本、随机安装标识、会话 ID。
- 用户确认后的 Android API 版本、厂商品牌和机型；不使用 IMEI、手机号或硬件序列号作为设备身份。
- 本应用启动/暂停、诊断会话开始/停止。
- 配置主页加载结果、耗时及预定义错误码；不发送任意浏览页面地址、查询参数、页面正文、表单内容、Cookie 或浏览记录。
- 用户主动发起的网络测试结果、有限会话心跳。

未来研究测试页的密码/短信场景只记录预设合成用例结果，例如 `case_id`、事件类型、`is_password`、`text_present`、`synthetic_value_matched`。真实密码、验证码、短信正文、输入文本及这些正文的散列均不进入日志。访问通道需显式区分节点、事件、通知监听和短信权限；不能用一个“已授权”字段混为一谈。

消息信封示意：

```json
{
  "schema_version": 1,
  "event_id": "RANDOM_EVENT_UUID",
  "build_id": "BUILD_UUID",
  "installation_id": "RANDOM_INSTALLATION_UUID",
  "session_id": "SESSION_UUID",
  "occurred_at": "2026-09-19T02:00:00Z",
  "type": "home_load_result",
  "data": { "success": true, "duration_ms": 420, "error_code": null }
}
```

`data` 不是任意 JSON 收集口；服务端按事件类型分别验证字段，拒收多余字段。项目归属从设备凭证解析，不信任客户端传来的 project_id。

## 5. 配对与接收接口（待实现）

- `POST /api/v1/enroll`：用户在手机端确认接收地址并输入一次性配对码；短有效期、限制尝试次数，绑定单个项目和安装实例。交换为独立、可撤销、限定诊断写入权限的设备凭证。
- `POST /api/v1/diagnostics/batch`：HTTPS、设备认证、限流、每批最多 50 条/64KB；依 event_id 去重。返回明确的已接收条目，客户端只移除确认成功的数据。
- `POST /api/v1/pairing/revoke`：撤销自身配对；撤销后停止提交、清空待发队列。
- 后台只读查看诊断记录；正式页面先完成登录和项目成员权限。

第一版复用 Laravel 验证、队列和数据库事务。设备凭证采用经过维护的认证组件，不自创签名协议。单台设备隔离额度；客户端限制队列总条数/总字节/存活时间、指数退避及随机抖动。401 停止提交并要求重新配对；429 按 Retry-After 重试，不忙循环。

公开域名 `yk.jk92.cc` 当前并未接入这些接口。现有免登录控制台保持本地访问，部署接收接口与公开管理页面是两个独立工作项。

## 6. 状态与容量

- 后台以服务器接收时间计算“最近联系”，不能用客户端时间或无障碍开关伪造在线状态。
- 当前服务端协议建议心跳间隔 1 秒；客户端尚未实现。后续仅在用户开启的研究连接中发送，网络失败和休眠视为连接状态未知。
- 1 万设备每秒一次心跳约为 1 万次/秒（不含帧与会话查询）。这只是算术估算，不是当前服务器的压测结论；当前 SQLite 小规模联调与限流配置不代表该容量。
- 批量诊断、严格限流、合理数据保留比简单更换 PHP 更重要；扩容需根据真实延迟、队列长度和数据库写入量测试。

## 7. 实施顺序

1. 先完成现有浏览器壳的真实编译、签名检查及 Telegram 附件送达。
2. 将包名/主页/通信配置抽成统一构建配置，补充字符转义、恶意参数、包名和地址校验测试。
3. 完成管理认证及手机端可见配对，接收本应用的固定诊断事件。
4. 加入撤销、限流、去重、数据保留和离线队列测试，再部署到服务器。
5. 有模拟器或登记测试机后验证应用行为；无障碍研究扩展以合成用例为单独阶段验收。

当前名称、图标和主页已进入真实构建流程，包名按构建自动生成。服务端接收接口详见 DEVICE_API.md，APK 尚未调用；通信地址配置与可见客户端会话仍待实现。

## 8. 已确认的连续诊断交互（设计更新，待实现）

用户确认在自己的测试设备上运行，希望体验类似投屏：不中断当前操作，但明确显示采集状态。此节定义后续客户端诊断模块；当前 APK 仅有浏览器和开关引导。服务器已实现租约和临时帧接收，不表示客户端已实现截图或节点上报。

### 开始与持续提示

- 用户在手机端开启本次诊断会话，界面写明接收服务器、全屏画面、研究节点范围及会话时长。启用无障碍服务与开启诊断是两个状态。
- 选择受支持系统的 AccessibilityService.takeScreenshot 路径；目标体验是不触发系统截屏动画、不抢焦点、不反复弹出确认框。每种系统/机型仍需实测，不承诺未经测试的性能和表现。
- 屏幕边缘显示小型诊断状态条：`● 诊断中 · 00:42  暂停  停止`。可移动，不覆盖关键控件，不主动获取输入焦点；条外区域继续正常操作。
- 提供持续通知，展示应用名称、正在共享屏幕、接收服务器和停止操作。避免每帧重复响铃或振动。
- 采集状态提示持续可见；若提示所需条件不具备，先解决提示显示，再开始会话，而非悄悄运行。
- 暂停会话同时暂停截图和节点采样，并显示“已暂停”；停止会话释放资源、清空待发数据。无障碍开关关闭后立即结束。

### 频率、范围与停止

- 截图覆盖整个显示屏，预览宽度与采样分辨率分开配置；系统受保护内容遵循平台限制。
- 目标上限每秒一张；上一帧尚未处理完成时不启动重叠采样，只保留最新结果。单帧目标用于诊断观察，不代表视频投屏的流畅帧率。
- 节点仅处理事先选定的研究测试页面，页面变化时采样，最多每秒一次；保留结构、坐标和属性，输入正文及真实凭证继续剔除。
- 图片和节点分别携带采样时刻；二者不是系统提供的原子快照，不假设绝对同步。
- 网页诊断租约与设备心跳分开。关闭页面尽力发送停止请求；租约失效时手机侧自行停止，服务器也停止接收该会话的数据。
- 初始租约可选 10 秒、网页每 3 秒续租；设备心跳不续诊断租约。失效会话使用新标识重新开始，旧数据不重放。
- 另设用户选定的最长会话时长；锁屏、设备停止、权限撤销、凭证失效和异常中断均结束采集。重连后不自动恢复已结束的会话。
- 全屏图像也可能带有私人信息，开始会话时提醒仅使用测试账号/测试内容。默认只做临时预览，不把每一帧永久归档；手动保存与留存期限另行明确。

### 验收重点

1. 在研究页面连续输入、滚动时，状态条不抢焦点，截图不触发额外弹窗或动画。
2. 暂停、停止、网页关闭、网页崩溃、网络中断、服务器中断均验证停止行为。
3. 检查锁屏、旋转、系统保护窗口、截图失败与低内存，不以绕过系统限制作为处理方式。
4. Android 版本与机型逐一记录实际能力、延迟和负载；当前无真机测试结果。

接口依据：[Android AccessibilityService.takeScreenshot](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshot(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))（API 30 起；服务需声明截图能力）。
