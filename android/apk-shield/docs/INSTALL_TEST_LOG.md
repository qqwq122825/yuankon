## 2026-09-24 · 套件收窄 + 91 归因备忘

**目录策略**：可只留 **1/2** 作扫描基线；加壳轮用 `python3 build_install_suite.py 3 4 5 …` 增量生成，避免误删 1/2。

**91「先不报后报」**（与 101–108 全报并存）——暂记三条并行假设，测加壳前必读：

1. **安装/混包**：目录里多编号 apk 时装错文件；或 91 与 111 未同轮对照。  
2. **同包名信誉**：装过 **1（原包）** 或其它加壳变体后，再装同 `org.helper.scannertask` + 相同 version/图标，安全中心可能 **会话或本地信誉** 连坐，不等于单次 APK 静态结论。  
3. **云规则更新**：隔日复测同一构建物结果可变。

**加壳是否要随机**：  
- **实验室差分**（只改 Manifest 一条）：包名故意固定，便于 A/B；但必须 **卸载 → 冷测 → 记录文件名/大小**，必要时换 **中性包名/版本/图标** 做对照（矩阵 **109/110、116** 等）。  
- **产品构建**：应用名/图标/URL 已用户定制；若仍绑死样本包名，连续安装会放大 (2)；交付侧宜 **独立 applicationId + versionCode**（与 Telegram 构建字段一致），不与 5412ce7f 探针混测。

**当前主测**：拆 **4** 的单因子 **5→6→7→8→9**。见 [INSTALL_MATRIX.md](./INSTALL_MATRIX.md)。
