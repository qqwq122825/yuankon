# resources.arsc 说明（5412ce7f 实验语境）

`resources.arsc` 是 APK 的**编译后资源表**，不是 App 的能力或权限清单。

| 部分 | 主要作用 |
|------|----------|
| **DEX / SO** | 程序代码，决定具体执行什么 |
| **Manifest** | 声明组件、权限、系统版本要求等 |
| **resources.arsc** | 字符串、颜色、样式等资源**值**，以及图片、布局等资源的**索引** |
| **res/** | 图片、布局、配置 XML 等资源**文件** |

运行时：代码要「编号 X 的按钮文字」→ 查资源表 → 再查 `res/` 里对应文件。  
扫描侧：安全中心可能解析 **arsc 和/或 res**，与 Manifest、DEX 是**不同通道**。

## 没有 arsc，App 还能用吗？

取决于 App **是否设计为依赖资源表**：

- 不依赖资源表的小壳/硬编码 UI → 可以没有 arsc。  
- **原本依赖资源表的应用**（如本样本）直接删掉 arsc → 可能出现文字/图标/页面缺失，甚至**启动崩溃**。  
- 资源里也可能含**功能配置**，因此 arsc **不只是外观**，缺失可能影响行为。

本样本（5412ce7f）资源表引用了 **963** 个 `res/` 条目（来自原包 ZIP 统计）。  
**删除 arsc 后是否仍保留功能，尚未实机验证**。

## 原包（1.apk）只删 arsc，功能会不会变？

**和 13/14/15/17「扫描正常」不是同一回事。**

| 包 | 实际是什么 |
|----|------------|
| **1** | 原 **DEX + 全 Manifest + arsc + 963×res** |
| **13** | **#90 线**（极瘦逻辑 + 大剥 Manifest + **改 DEX**）+ 从 91 **捐回** res/assets/lib，**故意无 arsc** |
| **18**（suite） | **原包重签后只删 `resources.arsc`**，其余与 1 同级（明文 DEX、全 Manifest、**res 全在**） |

对本样本这种**正常 Android 应用**：

- 代码里大量 `@R.xxx` / 资源 ID 依赖 **arsc 把 ID 映射到 res/ 文件**。
- **只删 arsc、保留 963 个 res 文件**：安装可能成功，但**极大概率**启动后图标/布局/字符串异常，甚至 **Resources$NotFoundException 崩溃**——**不能**默认「功能无影响」。
- **13 扫描不报**只说明当前引擎没按「那条包形态」命中，**不代表**「原包去掉 arsc 也一样能用」。

**18 实测（2026-09-24）**：原包重签、**只删 arsc** → **仍报毒**。说明引擎不只看 arsc；**13 不报** 是因为 **#90 线（改 DEX + Manifest 大剥）**，不是「删 arsc 就够了」。

### 为何 17.apk 比 18.apk 大？

| 包 | 约体积 | 要点 |
|----|--------|------|
| **18** | ~8.9 MB | 原包减 arsc：**963×res** + 原 **assets（~22KB）** + **lib** + **明文 DEX** + **全 Manifest** |
| **17** | ~17.6 MB | **#90 基线** + **91 的 assets（~6MB，含壳/payload 等）** + **lib**，**无 res、无 arsc** |
| **13** | ~19.8 MB | 在 17 思路上再加 **963×res** + 名 |

**17 大**主要是因为捐了 **加壳线的 assets（约 6MB）**，不是比 18「更完整原包」。**18 更小**是因为没有 arsc、且 **assets 仍是原证那小包**，但 **res + 原 DEX/Manifest 仍在**，所以扫描仍报。

**要实锤功能**：18 仍可装测能否打开（资源表缺失风险见上节）。

## 与扫描结论的关系

| 现象 | 含义 |
|------|------|
| **5 不报毒** | 仅改 Manifest 显示名，**扫描**未命中；**不等于**与原包同等功能。 |
| **7/8 不报** | 有 **res/** 但**无 arsc** 时，当前引擎未按原证 arsc 命中；安装器展示/运行可能异常。 |
| **6/9 报毒** | 原证 **resources.arsc** 是强特征（见 [ARSC_SCAN_REPORT.md](./ARSC_SCAN_REPORT.md)）。 |

## 套件策略（13 起）

- **优先**：探针 **故意不含 5412ce7f 的 arsc**（13、14、15…），换扫描结论与实机功能。  
- **需要 arsc 时**：必须用 **新构建** 生成的 arsc（Telegram/Gradle 模板），放入 `input/donor-arsc-source.apk` 再生成 **16**；**不要**复制样本 arsc。  
- **16 缺 donor 文件时**：构建脚本**跳过**并提示，不伪造 arsc。
